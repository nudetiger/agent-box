## Gradle setup misses local Maven dependencies of packet adapter subprojects

`delegate.sh setup /c/Workspace/Projects/MinecraftPlugins/RakunLoots --dry-run` proposes only the Gradle cache and a JDK. RakunLoots also resolves 18 Spigot packet adapter subprojects against local BuildTools Maven artifacts, with explicit `checkSpigotServer` tasks. A fresh worker image/cache cannot build its shadow jar without those artifacts even when host builds pass.

Workaround in this session: configure a persistent `/home/node/.m2` cache and seed `repository/org/spigotmc` from the host's existing BuildTools artifacts; leave the project's source/build unchanged. Setup should inspect `mavenLocal()` and local-artifact guards and warn that a baseline must provision them. Do not call missing artifacts an implementation/model failure.

## A project cannot request serial execution without competing for slot 1 globally

`slot_acquire` in `delegate.sh` uses the shared `runs/.slots` directory and loops over 1 through `AGENT_BOX_SLOTS`. Setting `AGENT_BOX_SLOTS=1` for this serial assignment restricts it to slot 1 even while unrelated projects occupy slots 1–3. It cannot use free slot 4. This is a global capacity limit, not a per-project concurrency limit.

Workaround: retain the harness capacity of 4 and launch exactly one RakunLoots worker/reviewer at a time; disable its scout and select `REVIEW_MODE=both` and `LOOP_FRESH=implement-hard`. Do not stop or modify the unrelated runs. A separate per-project semaphore would express this user's serial requirement directly.
## Base worker locale makes Java 17 compile UTF-8 source as US-ASCII

First RakunLoots baseline reached `:compileJava` with `-Dfile.encoding=US-ASCII` and emitted unmappable-character diagnostics for existing section-sign source text. Setup ultimately returned 0 despite those diagnostics; the baseline was deliberately restarted with UTF-8 while its tests were still running, so this is not recorded as a proven product test failure. The unchanged host passed both full `test` and root `:check`. This is a container environment failure, not a code regression.

Workaround: configure `LANG=C.UTF-8`, `LC_ALL=C.UTF-8`, and pass both via `CONTAINER_ENV` in this project's env. Java 17 uses the locale's encoding. The Gradle/JDK setup template should provide a UTF-8 locale, or the Java project should explicitly declare source encoding. This session chooses the environment fix to avoid unrelated product changes.
