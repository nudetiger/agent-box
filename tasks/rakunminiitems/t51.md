Implement GitHub issue #51: mobs cast MMOItems item abilities (ADR 0003). #49 and #50 are merged: `DashHandler` is registered with MythicLib in `onLoad`, `AbilitySession`, `AbilityFile` and `AbilityValues` exist.

The sealed test `MobTriggersTest` fixes the API of `MobTriggers`: `static boolean capable(String triggerName)` and `static boolean casts(String abilityId, String triggerName)`. Make it pass without editing it, and keep every other test green.

Facts from the jars in the Gradle cache (MythicLib-dist 1.7.1-SNAPSHOT, MMOItems-API 6.10.1-SNAPSHOT; read them with `javap` before writing calls):

- `TriggerType` is a class with public static fields (34 of them), not an enum. `TriggerType.valueOf(String)` and `values()` exist; custom triggers can be added from `triggers.yml`.
- An item's abilities are NBT `MMOITEMS_ABILITY`: a JSON array of objects (`Id`, `CastMode`, `Hide`, `Modifiers`). `NBTItem.get(item)` (`io.lumine.mythic.lib.api.item.NBTItem`) reads it. `new AbilityData(io.lumine.mythic.lib.gson.JsonObject)` parses one entry; `getTrigger()`, `getHandler()`, `getParameter(key)` (item modifier, then handler default).
- `SkillMetadata` has constructors without a `PlayerMetadata`, e.g. `SkillMetadata(Skill, Location source, Location target, Entity targetEntity, AttackMetadata)`. `getCaster()` is then null.
- `AbilityData.getResult`/`whenCast` apply the player's cooldown, mana and stamina through the caster's player data. A mob has none.

Build:

- `MobTriggers` (pure, no server, no Bukkit): `capable` is true exactly for `ATTACK`, `DAMAGED`, `DAMAGED_BY_ENTITY`, `DEATH`, `KILL_ENTITY`, `KILL_PLAYER`, `SHOOT_BOW`, `SHOOT_TRIDENT`, `TELEPORT`, case-insensitive and trimmed; null, blank, unknown and custom names are false. `casts(abilityId, trigger)` is false for Dash in any case and with any namespace prefix (`dash`, `DASH`, `rakunminiitems:dash`), false for a null id or trigger, else `capable(trigger)`.
- A mob ability listener, registered in `onEnable`. For a living entity that is not a player (MythicLib casts for players; never cast for a player here), it reads `MMOITEMS_ABILITY` on the armor, main hand and off hand, and casts each ability whose trigger matches the event and for which `MobTriggers.casts` is true. Events:
  - `ATTACK`: the mob deals damage, as the damager or as the shooter of the damaging projectile. Target: the victim.
  - `DAMAGED`: the mob takes any damage. `DAMAGED_BY_ENTITY`: damage from an entity (the projectile's shooter when there is one). Target: that entity.
  - `DEATH`: the mob dies. `KILL_ENTITY`: the mob kills any entity; `KILL_PLAYER`: the victim is a player (both fire on a player kill). Target: the victim.
  - `SHOOT_BOW`: `EntityShootBowEvent`. `SHOOT_TRIDENT`: a trident launched with the mob as shooter. `TELEPORT`: `EntityTeleportEvent`.
- The cast: build a `SkillMetadata` with no player caster (source the mob's location, the target above), then call the handler's `getResult` and, when it succeeds, `whenCast`; do not go through `AbilityData.getResult`/`whenCast`. Honour the ability's `cooldown` parameter per mob and per ability id, in an instance the plugin owns (not a static), forgotten when the mob dies or unloads. Ignore mana and stamina for mobs. A handler written for players may throw on a null caster: catch a `RuntimeException` per cast, skip that cast, and log it once per ability id at warning level. An unparseable entry or an unknown skill id is skipped silently.
- Keep the pieces that need no server (trigger matching from an event kind, the NBT array parsing into id and trigger, the per-mob cooldown with the time as a parameter) as testable code, and test them.
- A MMOItems ability NBT wins over any mark; the mark is 4b, so read only the MMOItems path. Dash already refuses a non-player caster; leave that as it is.
- README: a short line in the ability section saying which triggers a mob performs and that Dash is player only.

Out of scope: the mark path (4b), acquisition, Dash on mobs, mana or stamina for mobs, the projectile tick, hit and land triggers, `TIMER`. Follow `CODING_STANDARDS.md`.
