Implement GitHub issue #49: the end-to-end Dash slice. A player right clicks a sword whose MMOItems template gives it a Dash ability, and Dash fires.

The sealed test `DashTest` fixes the API of `Dash.velocity` and `FallWindow`. Make it pass without editing it, and keep every other test green.

Build:

- New package `me.rakkoon69.rakunminiitems.ability`. `Dash` and `FallWindow` are pure logic: no Bukkit server, no statics. `FallWindow` takes the current time as a parameter; the production caller passes `System.currentTimeMillis()`.
- A MythicLib `SkillHandler` for Dash, registered in `RakunMiniItemsPlugin.onLoad` through `MythicLib.plugin.getSkills()`. Register its modifiers with defaults read from `abilities/dash.yml`: velocity-percent 10, boost 0.5, window 3000 (millis), fall-reduction 100, particle `CLOUD`, particle-count 8, sound `ENTITY_BREEZE_WIND_BURST`, volume 0.4, pitch 1.2, radius 16. Cast-time values come from the item's `AbilityData.getParameter` chain (item override, then handler default). Read the MythicLib jar in the Gradle cache for the exact `SkillHandler` API; `docs/navigators/mmoitems-mythiclib.md` maps it.
- The cast: player only (a non-player caster does nothing). New velocity is `Dash.velocity(current, lookDirection, velocityPercent, boost)`. Then open or restart that holder's `FallWindow`. Then the particle and the sound at the holder's feet, heard within the radius. Window and cooldown state live in an instance the plugin owns, keyed by holder UUID.
- Cooldown 1 second as the SkillHandler cooldown default. The MythicLib-wins lookup rule is #50; do not build it here.
- A fall-damage listener registered in `onEnable`: on `EntityDamageEvent` with cause `FALL`, when the holder's window reduces now, multiply the damage by `1 - fall-reduction/100` (100 cancels it).
- Ship `src/main/resources/abilities/dash.yml` with those defaults and a short manual header, the way `stats/animals-bonus-damage.yml` does it. `PluginFiles` writes it when missing and reads the `abilities` folder, following the stat-files pattern.
- Reload re-reads the Dash values: follow the `statFiles` pattern through `Spine` and `ReloadCommand`, so `/rmi reload` picks up edited modifier defaults. Do not build the full ability-file machinery of #50 (name, trigger, item-groups, warning kinds); read only what Dash needs.
- The skill id is `DASH` so an MMOItems template can name it. MMOItems YAML `ability:`, `type: DASH`, `mode: RIGHT_CLICK` produces the NBT this path reads.

Out of scope: item group limits (#50), the MythicLib-first cooldown/cost lookup (#50), mob casting (#51), the mark path (4b), warning kinds for ability files (#50). Follow `CODING_STANDARDS.md`.
