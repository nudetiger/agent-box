Finish GitHub issue #51 under its new scope (the issue's latest comment, ADR 0003, `docs/phases.md` section 4). The live probe showed every built-in MythicLib skill throws on a mob, because `SkillMetadata.getCaster()` is null and every built-in needs a real `Player`. The fix: mobs cast only this plugin's own Abilities, by calling our code with the mob as holder. MythicLib is never called for a mob.

Required:
- Ability code takes a living holder. Add a small interface in `ability/` (for example `HolderAbility` with `boolean cast(LivingEntity holder, AbilityData data)`). `DashHandler` implements it: `cast(Player, AbilityData)` becomes `cast(LivingEntity, AbilityData)`. Look is `holder.getLocation().getDirection()` (a mob's eye direction). The MythicLib player path (`whenCast`) passes the caster's `Player` into the same method. The fall window keeps keying on the entity UUID.
- `MobTriggers.casts`: drop the Dash exclusion. Every ability casts on a mob-capable trigger, no other.
- `MobAbilityListener.executeCast` gains a `String trigger` parameter after `abilityId`: `executeCast(SkillHandler<?> handler, AbilityData data, String abilityId, String trigger, LivingEntity mob, Location sourceLoc, Location targetLoc, Entity targetEntity, long now)`. When the handler is one of this plugin's abilities (implements the interface), call its `cast(mob, data)` directly, keeping the per-mob cooldown, the per-mob re-entrancy guard and the item-group check. Any other handler (a built-in MythicLib skill) is skipped: no `getResult`, no `whenCast`, no log line. Remove `warnedAbilities` and `logWarningOnce`. A `RuntimeException` from our own ability still must not escape the listener.
- Debug line: add the constructor `MobAbilityListener(Logger, AbilitySession, MobCooldowns, Consumer<String> debug)`. Each successful mob cast sends one line with the mob type (`getType()`, null-safe), mob UUID, ability id and trigger. Wire it to the existing `debug` config switch the same way `boot/Spine.java` builds the command registry's debug consumer (`logger.info(line)` only while `debug()` is true, so a reload toggles it), and pass it where `RakunMiniItemsPlugin` registers the listener. Other constructors pass a no-op.
- Update existing tests that encode the old rules (`MobTriggersTest` Dash exclusion, `MobAbilityListenerTest` warnings and casts through arbitrary `SkillHandler`s, `DashHandlerTest` calls). Keep what they prove (re-entrancy, cooldowns, trigger matching) by using a fake that implements the new interface.
- Make the sealed test pass without editing it. Keep every other test green.

Out of scope: mark path (Phase 4b), new abilities, ported built-ins, config files, docs.
