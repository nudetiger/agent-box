Implement GitHub issue #50: ability files, the shared lookup rule, and item group limits. #49 is merged: `Dash`, `FallWindow`, `DashConfig`, `DashHandler`, `FallDamageListener`, `abilities/dash.yml`, and the reload path through `Spine`/`ReloadCommand` exist.

The sealed tests `AbilityFileTest` and `AbilityValuesTest` fix the API of `AbilitySession`, `AbilityFile`, and `AbilityValues`. Make them pass without editing them, and keep every other test green.

Facts from the MythicLib/MMOItems source (gitlab.com/phoenix-dvpmt, master):

- `AbilityData.getParameter(key)`: item modifier wins, else `handler.getDefaultItemParameter(key)`. `AbilityData.hasModifier` checks the item map.
- `SkillHandler.getDefaultItemParameter(key)` returns the `SkillParameter` item default, 0 when the key was never registered. Base modifiers `cooldown`, `mana`, `stamina` are always initialized from the handler's config section (`parameters.<key>`).
- MMOItems already applies cooldown, mana, and stamina itself in `AbilityData.getResult`/`whenCast` from `meta.getParameter("cooldown"|"mana"|"stamina")`. So the handler must publish its cooldown/mana/stamina defaults as handler parameters, and `DashHandler`'s own cooldown map is a second path. Remove the duplicate: the cooldown check in `getResult`/`cast` goes through `AbilityValues` and MMOItems' own application. Keep the direct `cast(player, abilityData)` entry point working for tests and the later mob path (#51).

Build:

- `AbilitySession` (knows Dash only, mirroring `EnchantSession`): `open(Map<String,String> files, ItemGroups groups)`, `ability(String id)`, `allows(String id, String itemKey)`, `reload(files, groups)`, `warnings()`. Resolves `item-groups` through `ItemGroups.resolve`. Empty list means no limit; a missing key keeps the shipped default `['@swords']`.
- `AbilityFile` record: framework fields `name`, `trigger` (a free string; every TriggerType is accepted, do not validate against an enum), `itemGroups`, `cooldown`, `mana`, `stamina`, plus `modifiers()` returning `DashConfig`. Move `cooldown` out of `DashConfig`; add `mana`/`stamina` at the framework level. Bad values warn and keep the shipped default, following the existing warning wording (`dash.yml: unusable key cooldown, the cooldown stays 1`) and the warning-kind machinery the stat and enchant sessions use (a severity per kind through `warnings.yml`).
- Unknown `particle`/`sound` keys: validate server-free against the Bukkit enums at parse time, warn (`dash.yml: unknown particle NOT_A_PARTICLE, the particle effect is skipped`), and set the value null so the cast skips that effect. This replaces #49's silent fallback to CLOUD; `DashHandler.cast` must treat a null particle/sound as "no effect".
- `AbilityValues.value(AbilityData data, SkillHandler handler, String key, double fileDefault)`: item modifier wins, then the handler's parameter when it carries a value, then the file default. Use it in `DashHandler` for cooldown, mana, stamina, and every numeric modifier, replacing the current `getParam`.
- `DashHandler.update` is fed from the reloaded `AbilityFile` (cooldown/mana/stamina become handler parameters, so MMOItems applies them on its own cast path). `Spine`/`ReloadCommand` swap their Dash-only reading for the `AbilitySession`, logging its warnings the way stat and enchant warnings are logged.
- The group limit on the player cast: MythicLib casts for players, so enforce inside the handler's `getResult`/`whenCast`: resolve the casting item's base item key and refuse when `allows` is false. Read how MMOItems passes the item into the cast (`SkillMetadata`, the MMOItems trigger listeners on GitLab) before choosing the mechanism.
- Update `abilities/dash.yml` (add `name`, `trigger`, `item-groups: ['@swords']`, `mana`, `stamina`) with the manual header, and update the README's ability section so a server-side agent can edit the file.

Out of scope: mob casting (#51), the mark path (4b), acquisition. Follow `CODING_STANDARDS.md`.
