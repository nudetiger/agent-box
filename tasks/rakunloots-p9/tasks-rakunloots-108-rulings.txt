## Full-spec recheck p9-108-spec-full: six new points, all ruled
F1 (new point1): Default soundExists returns false (strict by default), preserving NameCatalog as a functional interface with one abstract method. BukkitNameCatalog overrides it with the real Registry.SOUNDS check. F2 (new point2): Missing-file defaults are read from the jar as prevalidated shipped data and applied silently, including with NameCatalog.empty(). Do not inject extra unknown-id/sound warnings into pre-existing pure config tests just because menu defaults now exist. Written files still get actual caller-catalog validation. Whole-file fallback uses the shipped layout as specified, with exactly one severe fallback warning.
F3 (new point3): Missing rows/content_slots uses the shipped page values silently. Present-invalid values follow documented validation. F4 (new point4): A missing wiki list/loot page gets that shipped page silently, while preserving a valid customized other page. A present page that ends without content triggers whole-wiki fallback, as required.
F5 (new point5): A present known button with omitted slot/item inherits the same-name shipped values silently. Unusable item warns via existing item parser and uses that shipped item. A present invalid slot or an effective slot outside chosen rows warns high and drops the button, never clamps it to an invented slot. A button omitted from buttons is not shown; do not repopulate omitted buttons. A syntactically valid runtime-unresolvable item reference remains for #109 barrier behaviour.
F6 (new point6): A present sound block with a missing, non-string or unusable key warns high and leaves the button silent, using the new sound warning kind. An entirely omitted sound block is silent without warning, including info. Do not silently restore a shipped sound to an explicit invalid sound.
