Implement T198 (issue #53): the vitest reporter adapter and the exit-code fallback, inside `runSealedTests` in `lykos/seal/runner.ts` (the one function the red check, and later T201's green run, call).

The sealed test `lykos/cli/seal-t198.test.ts` runs the real `lykos seal create` with the vitest installed in Lykos's own node_modules, through the template `node <vitest.mjs> run --globals --reporter=json {files}`.

- Add `vitest` 5.0.3 (exact, released 2026-09-30) as a devDependency and update package-lock.json with `npm install --save-dev --save-exact vitest@5.0.3`. Add a short intake note in `research/` (what it is, version, why a devDependency, license) in the style of the existing intake notes.
- Adapter selection from the template: a template that runs `vitest` uses the vitest adapter; one that runs `node --test` (or `node ... --test`) uses the node:test adapter; anything else uses exit-code mode. The seal's `adapter` field is `node:test`, `vitest` or `exit`.
- vitest adapter: inject a JSON reporter output file (`--outputFile=<tmp>.json` alongside `--reporter=json`; keep the user's own `--reporter=json` if present) and read per-test results: file (repo-relative), full describe path (`ancestorTitles`), name (`title`), status. Failed by assertion = red; a file that failed to load (import error, a suite with `failureMessage` and no tests) = `errored`; `skipped`/`pending`/`todo` = `not collected`; a matched file with no tests = `not collected`; `passed` = `passed`. Refusal lines name file, test and reason, as T195's do.
- Exit-code mode: run the template once; a non-zero exit seals with `adapter: "exit"`, `red: []`, and prints a warning containing "exit-code mode" and "weaker" (no per-test evidence); exit 0 refuses ("the test command passed").
- Strip `VITEST` and `NODE_TEST_CONTEXT` from the test environment (T195 does already; keep it).
- Default `seal.test_command` stays T195's; document the vitest template `npx vitest run --reporter=json {files}` in the config reference and check the flags against vitest 5.0.3's own CLI help before relying on them.

Out of scope: the gate's green run (T201), any jest/mocha adapter.
