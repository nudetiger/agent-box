Fix issue #79.

1. **The option** (lykos/tools/executor.ts). `ExecSpawnOptions` gains `containerPaths?: boolean`, documented in the file's style: true returns stdout and stderr as the command wrote them, with `/work` paths untranslated; set only by a caller that parses the output and never shows it to the model. The local executor must not pass it on to `child_process.spawn`.
2. **The container executor honours it** (lykos/containment/containment.ts). `containerExecutor().spawn` passes it to `ContainerChild`, which then pipes the inner stdout and stderr straight through instead of through `hostPathsIn`. `shellOperations` (model-facing) never sets it.
3. **The runner sets it** (lykos/seal/runner.ts) on every `executor.spawn` it makes (three call sites). The reported-path mapping (`mapReportedPath`) already maps a `/work/...` path to its sealed file by suffix; keep that, and keep the T210 stdout parsing.
4. A short note in the seal or containment reference doc saying the sealed runner reads untranslated output and why (Windows paths break JSON).

Out of scope: changing `paths.ts` translation itself, vitest under a read-only `.lykos/` (separate gap).
