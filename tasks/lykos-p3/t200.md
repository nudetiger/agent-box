Implement T200 (issue #55): `lykos seal hook install` and pruning merged seals on `seal create`.

- `lykos seal hook install` writes a git pre-push hook into the repository's real hooks directory (`git rev-parse --git-path hooks`, which honours `core.hooksPath` and worktrees). The hook runs `lykos seal verify` (the same `verifySeals` code path) and exits non-zero when it fails; with no active seal it passes.
- An existing pre-push hook is never silently overwritten: keep its behaviour (chain to it, or append a marked Lykos block) so both run, and installing twice does not duplicate the Lykos part. Print what was done.
- Pruning: `seal create` deletes the seal files of seals already merged into the seal's base (the existing "merged" definition: the seal commit is reachable from `base`), and keeps every unmerged one. The deletions go in the same signed seal commit `create` makes, so verify never sees an unsigned deletion of an active seal. `verify` must still pass after a prune.
- A deleted active (unmerged) seal file stays tampering, as now. Do not weaken that rule.
- Document `seal hook install` and pruning in the CLI reference.
