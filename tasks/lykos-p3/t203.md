Implement T203 (issue #58): `dispute_test`, registered by lykos-seal, and the `disputed` session end.

- `dispute_test({file, describe, name, reason, evidence})` records a `seal_events` row (kind `dispute filed`, detail holds reason and evidence) and parks that test. The tool returns at once; the session continues.
- At session end, T201's gate check still fails on a parked test. When every failing sealed test is parked, the ledger outcome stays `fail` and the task state becomes `disputed`. Any other failure: an ordinary fail.
- `lykos show` lists each dispute (test, reason, evidence) and shows `disputed`.
- Config: `seal.resolver` (`orchestrator` | `test-writer`, default `test-writer`) and `seal.escalate_after` (default 1). Only `orchestrator` behaves in this ticket; `test-writer` is T204 and today falls back to the orchestrator behaviour.
- `orchestrator` resolver: a spawned child's dispute reaches its parent in the child's agent tool result (test, reason, `disputed`). The parent's ruling reaches the implementer through the existing follow-up path to that child.
- With `lykos_extensions: []`, `dispute_test` does not exist.

Out of scope: test-writer resolution, escalation and upheld counts (T204).
