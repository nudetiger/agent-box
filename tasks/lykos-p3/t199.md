Implement T199 (issue #54): the `tool_call` veto on the Lykos extension API and the `lykos-seal` default extension.

The sealed test `lykos/cli/scripted-seal-veto-t199.test.ts` runs real scripted sessions (`lykos/cli/scripted-session.ts`) in a workspace sealed by the real `lykos seal key init` and `lykos seal create`.

- Core: expose Pi's existing `tool_call` event through `lykos/extensions/api.ts` as a block-only veto (allow, or block with a reason; never rewrites arguments). It must see mounted tools by their real name (`resolveActualToolName`, see `loop/harness-extension.ts`). A blocked call returns an error result carrying the reason. No new interception layer.
- `lykos-seal` is a default Lykos extension in `config/defaults.ts` `lykos_extensions:` (ADR-0028 list); a project `lykos_extensions: []` removes it. Config keys `seal.writers` (default `[test-writer]`) and `seal.enforce_for` (default `[implementer]`), keyed by specialist name.
- For a session whose specialist is in `enforce_for` and whose HEAD has an active seal (`activeSeals` from `lykos/seal/active.ts`, found through history, never by branch name), block `edit`, `write`, `ast_edit` (built-in or mounted) on sealed paths. The reason names the seal and tells the model to call `dispute_test` instead. Match paths with the matcher in `gate/path-rules.ts`.
- `bash` and `powershell` commands naming a sealed path (found through `gate/bash-paths.ts`) run, and the tool result carries a warning naming the sealed path.
- Test command allowance: for a specialist in `writers` or `enforce_for`, when HEAD has an active seal, a bash command equal to the seal's recorded `test_command` template with `{files}` replaced by one or more files matching `seal.test_globs` is allowed without asking, in every interaction mode (plan is a specialist now; a `plan` specialist is in neither list by default and gets nothing). Every other command is decided by the normal permission rules, unchanged.
- Ledger: `vetoed` (one per blocked call) and `bash-warned` rows in `seal_events` with the session id and specialist; `lykos show` renders them (a line containing "veto").
- Compute the active seals once at session start (they cannot change without a commit; recompute after a commit by the session if cheap), never per tool call by spawning many git processes.

Out of scope: `dispute_test` itself (T203), the gate check (T201), MCP (T206).
