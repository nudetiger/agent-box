Fix the three defects in issue #77, found by the first live `npm run phase3:live`.

1. **Contained green run** (lykos/seal/runner.ts). A reporter file written inside a container names files by container path (`/work/...`). Map each reported file to the sealed file it is: a reported path whose `/`-normalised form ends with `/` + one of `opts.files` is that file. Apply it to both adapters that read a reporter file from disk (node:test's `--test-reporter-destination` and vitest's `--outputFile`). Do not translate through containment internals; the runner only knows `opts.dir` and `opts.files`.
2. **dispute filed** (lykos/extensions/defaults/lykos-seal.ts). Every dispute_test call that passes its own checks writes exactly one `dispute filed` event before anything else it records, in every resolver path (test-writer, orchestrator, child). The dispute count behind `escalate_after` counts disputes, so a filed dispute and its ruling are one dispute, not two: the existing T204 escalation test must stay green unchanged.
3. **The demo script** (lykos/session/phase3-acceptance.ts, run by the maintainer, never in the container):
   - Two implementer sessions. Session 1 is told to try the edit tool on the sealed test, then append to it through `bash`, and then stop without reverting. Assert from the ledger: a `vetoed` event, a `tampered` event, and session 1's outcome `fail`.
   - Between the sessions the script itself restores the test from git (`git checkout -- <file>` run by the script on the host) and prints that it did.
   - Session 2 disputes, the test writer upholds and reseals, it implements and commits. Assert `dispute filed`, `dispute upheld` by test-writer, a second `created`, `lykos seal verify` exit 0, and session 2's outcome `success` with exit code 0.
   - The `lykos show` text check for the green gate must require the verdict `success`, never `exit code 0` alone. Print `lykos show` for both sessions.
   - Update phase3-acceptance.test.ts for the new shape (no paid calls in it).
