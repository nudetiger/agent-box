Fix issue #78.

1. **Results come from stdout** (lykos/seal/runner.ts). A contained command's directory may be read-only (`.lykos/` is, in every container), so the runner must never depend on a file the command writes. node:test: send the custom reporter to stdout (`--test-reporter-destination=stdout`) and parse the JSON lines from stdout, skipping lines that are not JSON. Keep the reporter `.cjs` file: the host writes it, and the command only reads it. vitest: drop `--outputFile` and read the json reporter from stdout the same way. T209's suffix mapping of reported paths stays.
2. **Say what failed** (lykos/extensions/defaults/lykos-seal.ts, the gate's green run). When the runner returned errors and collected no tests, the block reason and the seal event's detail carry the runner's errors. Do not report "not collected" for each red test in that case.
3. **Demo script prompts** (lykos/session/phase3-acceptance.ts). In the second live run the session 1 model refused the bash append ("defeating the guard") and disputed instead, so session 2 had nothing to dispute.
   - Session 1's prompt says this is the maintainer's authorised check that the gate catches a sealed test changed through bash. It tells the model that its session is expected to fail, and that it must not call dispute_test or implement anything.
   - Session 2 is unchanged.
   - Update phase3-acceptance.test.ts if it asserts the prompt text.
