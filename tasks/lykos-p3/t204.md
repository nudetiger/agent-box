Implement T204 (issue #59): the `test-writer` resolver for `dispute_test`, and escalation.

- The extension API gains a writable child session beside T149's read-only one, gated as a spawned specialist is. lykos-seal runs the test writer in it for a dispute.
- Upheld or rejected is decided by the result, not by the child's words: the disputed test file changed in the child's commits means upheld; unchanged means rejected, and the child's final text is the ruling.
- Upheld: lykos-seal reseals from HEAD (a writer is never blocked by its own seal), unparks the test, and dispute_test answers `upheld`. Rejected: the test stays sealed and dispute_test answers `rejected` with the ruling.
- Escalation: a test disputed more than `seal.escalate_after` times (default 1) skips the test writer and goes to the orchestrator (the parent session, through T203's path, when the implementer was spawned), then to a human through `ask` when a human channel exists. With neither, dispute_test answers `escalated`, the test stays parked and the session ends `disputed`.
- seal_events kinds `dispute upheld`, `dispute rejected`, `dispute escalated`, with `specialist` set to the resolving test writer's name. `lykos show` lists them.
- Add a unit test for the spawned-implementer escalation to the parent.
