Implement T195 (issue #50): `lykos seal key init`, `create [<commit>]` and `status`, on a new pure core module `lykos/seal/` that is the only place computing sealed paths or active seals (T197 verify and T199 the veto reuse it).

The sealed test `lykos/cli/seal-t195.test.ts` drives the real CLI in a temporary git repo with HOME/USERPROFILE set to a temp dir, and pins:
- the config block `seal:` in `.lykos/config.yaml` with keys `base` (default: the repo's default branch: origin/HEAD, else `init.defaultBranch`, else `master`/`main` whichever exists), `test_command` (a `{files}` template; default `node --import tsx --test {files}`), `test_globs`, `always_sealed`. Add `seal` to the config types and validation; unknown sub-keys are an error like other blocks.
- the seal file `.lykos/seals/<branch>.json` (snake_case JSON): `version`, `branch`, `writer_commit`, `creator` (session id or `cli`), `specialist` (or null), `sealed_paths` (sorted, repo-relative, forward slashes), `test_command` (the template), `adapter` (`node:test`), `red` (array of `{ file, describe: string[], name, failure }`, `failure` being the failure kind such as `assertion`), `created_at`, `key_id`, `signature`.
- The seal commit is the commit that adds the seal file; it is found from history, never recorded inside the file (a commit cannot name itself).
- Signing: ed25519 via `node:crypto`, no dependency. The signature covers the canonical JSON of every other field. Private key under `~/.lykos/` (e.g. `~/.lykos/seal-keys/<key id>.pem`, mode 0600), never in the repo. Public key committed at `.lykos/seals/keys/<key id>.pub` by `key init` (one commit). `key_id` is a stable fingerprint of the public key (e.g. first 16 hex of its sha256).
- `create`: checkout the writer commit (default HEAD) in a clean temporary `git worktree`; run the template with `{files}` = the sealed test files through a `node:test` reporter adapter (inject a machine-readable reporter, e.g. `--test-reporter=tap` or a custom reporter file, without asking the user to change the template); every sealed test must have executed and failed by assertion. Refuse with one line per offender naming file, test and reason `passed`, `errored` (import/compile/file-level error) or `not collected` (skipped, todo, or a matched file that ran no test). Refuse duplicate identities (file + full describe path + name). On success write, sign and commit the seal file (message `seal: <branch>`), leaving any dirty working tree untouched (commit only the seal file; use a pathspec commit or a temporary index, never `git add -A`). A reseal replaces the branch's file.
- Sealed paths = files changed by the writer commit (vs its first parent) matching `test_globs` (default `**/*.test.*`, `**/*.spec.*`, `test/**`, `tests/**`, `**/__tests__/**`), plus files present in the tree matching `always_sealed` (default: runner config/setup files such as `vitest.config.*`, `vitest.setup.*`, `jest.config.*`, `.mocharc*`, `**/fixtures/**`, `**/__fixtures__/**`, `**/__snapshots__/**`), plus the seal file. Match with the glob matcher of `lykos/gate/path-rules.ts` if it fits, else one small matcher in the seal module.
- Active seals of HEAD: seal files added by a commit between `merge-base(HEAD, seal.base)` and HEAD (`git log --diff-filter=A -- .lykos/seals/*.json`, excluding `keys/`) whose branch is not merged into `seal.base`. Never look a seal up by the current branch name. `status` prints, per active seal: branch label, seal commit sha, writer commit, sealed paths, and each red test (file, describe path, name); with none it prints `no active seal` and exits 0.
- Executor: the red run uses the executor config resolves to (`lykos/tools/executor.ts`; `localExecutor` when containment is off, which is the default; when containment is on, the contained executor for the temporary worktree). Keep the run behind one function so T201 and T206 reuse it with a session's executor.
- Ledger: record a `created` seal event (session or `cli`, specialist, branch, paths). Add a small `seal_events` table (migration in the ledger's existing style) with columns at least `ts, session_id, specialist, branch, kind, paths(JSON), detail`; T197–T203 add the other kinds. Check the current session/specialist fields in `lykos/ledger/ledger.ts` first (P2's third band changed them).
- Add seal-module unit tests beside it (`lykos/seal/*.test.ts`) for the glob filter, active-seal discovery and signing. Document the command in `docs/reference/` (cli reference) and the `seal:` block in the config reference.

Out of scope: `verify` (T197), the vitest adapter and the exit-code fallback (T198), the veto (T199), hook install and pruning (T200), MCP.
