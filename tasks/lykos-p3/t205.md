Implement T205 (issue #60): ship `test-writer` and `implementer` specialists and a `sealed-tdd` skill.

- `lykos/specialists/test-writer.yaml` and `lykos/specialists/implementer.yaml`, in the T214 format (read `build.yaml` and `lykos/config/specialists.ts` for the fields; check `read_only`, `role` and permission defaults against source). Neither is read-only. Each has a one-line `description` and `instructions`.
  - test-writer: writes failing tests and the stubs they import, so each test fails on an assertion (not an import error); commits them; does not implement.
  - implementer: makes the sealed tests pass and may add its own tests; never edits a sealed test; when it believes a sealed test is wrong it calls `dispute_test` with the test, its reason and its evidence instead of working around it (Anthropic's guidance and ImpossibleBench: an explicit way out cuts cheating).
- A `sealed-tdd` skill scaffolded by `lykos init` into `.lykos/skills/` beside `finishing-work.md`, written with `writeIfAbsent` so a project's own file is kept. It describes the loop: test-writer writes red tests and commits, `lykos seal create` seals them, implementer makes them green, a wrong test is disputed, the gate checks the seal.
- Do not change `build.yaml` or any other shipped specialist. Nothing depends on a ticket format.
