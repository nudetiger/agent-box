Implement T201 (issue #56): the block-only gate check seam in core, and the lykos-seal check that uses it.

- Core seam: an extension registers a gate check through the extension API. The session gate runs every registered check after its own command. A check returns pass or block with a reason. A block turns success into failure and records the reason in the ledger. A check can never produce success: `runVerify` stays the only writer of `outcome = 'success'`.
- The seal check must run even for a session whose only file changes came through `bash` (today such a session may have no gate outcome at all). A session that touched a sealed file in any way must end failed.
- lykos-seal check: call `verifySeals` (core), then the green run: `runSealedTests` in a clean temporary checkout of HEAD (`git worktree add --detach` or an archive export, never the working tree; untracked and uncommitted files do not count), through the session's `ProjectExecutor`, with `{files}` = the sealed test files. Every test recorded at red must have run and passed; one not collected fails. Exit-code mode requires exit 0 and reports the weaker mode. Clean up the checkout.
- In an enforced specialist's session (`seal.enforce_for`), reject any seal whose seal commit is not an ancestor of the commit the session started from, whoever made it; the creator field is a record only.
- The failure names the changed sealed files, in the ledger and in `lykos show`. An uncontained session's `lykos show` states the guarantee was weaker (the session's shell could read the signing key); a contained one does not.
- Document the seam in the extensions reference.

Out of scope: weakening patterns (T202), disputes (T203).
