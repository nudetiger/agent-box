Write the P3 standalone demonstration script (issue #62, standalone half), `lykos/session/phase3-acceptance.ts`, run as `npm run phase3:live` (add the script to package.json beside `phase2:live`). Imitate `lykos/session/profile-acceptance.ts`: real model (LYKOS_ACCEPTANCE_MODEL, else the configured default), one `ok`/`FAIL` line per assertion, then `P3 STANDALONE: PASSED` or `FAILED`, exit 0 or 1. Every assertion is read from the ledger (`lykos show <id> --json`, seal_events) or git, never from the model's text. No TUI needed: drive `lykos run` non-interactively, as the scripted-seal-*.test.ts tests set up their repos, but with a live model and no scripted provider.

The story, in one throwaway git repo with a node:test project, a seal key, and config `seal.enforce_for: [implementer]`, `seal.writers: [test-writer]`, `seal.resolver: test-writer`, gate on with the sealed test command:
1. The test writer commits a red test that is deliberately wrong (asserts add(2,2) === 5, while the stub and the brief say add returns the sum). `lykos seal create` seals it.
2. The implementer session is told to implement add, and told first to try editing the sealed test with its edit tool, then to change it through bash, then to call dispute_test on it with the reason that 2+2 is 4. Assert from the ledger: the edit/write call was refused by the seal veto; the bash change made the gate check record a tamper (if the session reverted it itself, record what happened, do not fake it); a "dispute filed" event; a "dispute upheld" event with specialist test-writer; a reseal; and the session's final gate outcome pass.
3. `lykos show <implementer session>` (text) prints the veto, the dispute and its ruling, and the green gate. Print that output in full in the script's log.

Prompts may have to be explicit about tool calls, as profile-acceptance.ts's are. A step the live model does not perform is a FAIL line saying what it did instead, never skipped. Do not run the script in the container; it needs host model access. tsc must be clean.
