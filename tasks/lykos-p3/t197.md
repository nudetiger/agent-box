Implement T197 (issue #52): `lykos seal verify [--branch <name>]` on top of the T195 seal module in `lykos/seal/`.

The sealed test `lykos/cli/seal-t197.test.ts` drives the real CLI in a temporary repo. Use `activeSeals` from `lykos/seal/active.ts` (the one place that finds active seals through history); extend it rather than writing a second discovery. Expose the check as one exported pure function (e.g. `verifySeals({cwd, env, base, branch})` returning per-seal results with causes) so T200's pre-push hook and T201's gate call it.

Each failure line names the cause: the changed sealed paths, `seal file modified`/`seal file deleted`, an untrusted key or a key not present at merge-base, an invalid signature, a changed test command (`test_command` differs from `seal.test_command` in the config at HEAD), a seal commit that is not an ancestor of HEAD (writer commit not in HEAD's history). A HEAD with no active seal prints `no active seal` and exits 0. Uncommitted changes are ignored: verify compares commits (seal commit to HEAD), never the working tree. Verify never runs project code: only git and signature checks.

A seal file deleted or missing at HEAD is tampering unless a later signed seal commit pruned it (T200 builds the pruning; here, accept a deletion only when the commit that deleted it is itself a valid signed seal commit of another branch).

Record `verified` or `tampered` in `seal_events` (`recordSealEvent`, detail naming the causes). Document `verify` in the CLI reference.

Out of scope: hook install and pruning (T200), the gate (T201), the veto (T199).
